# Monsters domain

Game-ready **pixel-art monsters** for the Nangijala game, generated with
[PixelLab](https://pixellab.ai) as the drawing backend.

This is one **domain** of the multi-domain `pixel` repo, owned by the
**monsters agent**. It is self-contained: everything lives under `monsters/`.
See `coordination/PROTOCOL.md` for the fleet contract.

## Ground truth: the MONSTER tag

The maintainer authors monsters in the PixelLab web UI — in **either** store:

- **objects** (create-object UI, `v2/objects`) — free-form sprites with text
  animations;
- **characters** (create-character UI, `v2/characters`) — rigged on skeleton
  templates (Bear, Cat, Dog, Horse, Lion, …).

Every monster is tagged **`MONSTER`** on PixelLab. That tag is the single
source of truth for *which* monsters exist: `sync.py` discovers by tag across
both stores, mirrors every tagged monster in, and **prunes** any repo folder
whose PixelLab entry was deleted or untagged. PixelLab is also the source of
truth for the *art* — regenerate/refine there, resync here (zero generations).

## The 5 game states

Every monster serves the same logical states: **idle, walk, angry, attack,
die**. The maintainer words animations freely in the UI (a walk might be
prompted as "Jumps like a frog"), so each roster entry carries `renames`
mapping the exact PixelLab animation names to canonical keys — on disk every
monster exposes the same `animations/idle|walk|angry|attack|die/` folders.

**`animation_map.json`** (same contract shape as
`characters2/animation_map.json`) is what the game reads: `states` holds the
identity defaults, `overrides.<id>` the deviations — e.g. `{"angry": "idle"}`
means *this monster has no angry animation; play idle for both* (maintainer
rule) — and `missing` lists states a monster cannot serve yet (art still to be
generated on PixelLab). It is regenerated by every sync from
`config/roster.json`.

**`angry → idle` is a finished state, not a missing one.** Some creatures
already look angry standing still, so their idle serves both and no separate
clip is wanted (maintainer, 2026-08-13). Don't chase those as gaps or report
them as issues — the only real gaps are states listed under `missing`.

## Layout: one folder per monster

```
monsters/<id>/
  monster.json                     manifest: source, sizes, animations, resolved
                                   states, and `lore` — a short RPG-flavour
                                   blurb (~95-120 chars, sized to the wiki's
                                   monster header) authored in config/roster.json
                                   and carried into the manifest by every sync
  sprite.webp                      base sprite (south rotation)
  rotations/<dir>.webp             8 directions
  animations/<state>/<dir>/NN.webp per-frame art
  animations/<state>__<dir>.webp   sprite-sheet strip
```

**57 monsters** (2026-08-13): 20 authored in the objects store, 37 in the
characters store. All serve 5 states × 8 directions, bar two upstream gaps —
`plague_hound` has no attack (see `animation_map.json:missing`) and
`magma_wolf` no angry (falls back to idle).

**Everything writes art through `mirror._save_png` / `_save_strip`**, never a
raw `Image.save`. Those helpers force `config/format.json:art_ext`, so a
hardcoded `.png` silently drops a PNG into a WebP-only tree — which is exactly
what `trim_die_tails` did until 2026-08-13 (572 files). Paths that *read* art
accept either extension; paths that *write* it must go through the helpers, and
paths that *name* a file (`sprite.png`) must go through `_art_path`.

## Review gallery (chat artifact, NOT in git)

The review gallery is a **claude.ai artifact** the maintainer views in chat —
every monster, one line per state, each clip playing through then turning one
45° step, all the way around. Fallbacks (`angry → idle`) and MISSING states
are labeled. It is deliberately not committed; after a resync, regenerate and
republish it:

```bash
python monsters/pipeline/review_artifact.py -o /tmp/monster_review.html
# then the agent republishes it to the existing artifact URL
```

(A future wiki is a separate task and not this gallery.)

## Art format: lossless WebP



The domain is **lossless WebP** (converted 2026-07-31). `config/format.json:art_ext`
decides what the pipeline WRITES; it READS either `.png` or `.webp`:

```bash
python monsters/pipeline/to_webp.py --dry-run        # measure per class
python monsters/pipeline/to_webp.py --class all      # convert + verify + retarget
python monsters/pipeline/to_webp.py --revert --class all
```

Result: **9044 files, 35.87 MB -> 11.92 MB (66.8% smaller)**, no file bigger.
Every conversion re-decodes and compares RGBA against the source and aborts on
any mismatch, and `exact=true` keeps RGB under transparent pixels intact.

Both consumers read either format: the game via `games2/scripts/imagelib.mjs`
(and its `resolveImg` follows a stale `.png`/`.webp` in a manifest), the wiki
via its own `ART_EXTS`. Verified after converting: the game's `monsters.json`
is identical modulo extension for 24/24 monsters, wiki build clean.

**No GIFs.** The per-direction and rotating preview GIFs were deleted
(1023 files, 17.5 MB) once neither consumer read them — the wiki's viewer
draws frames onto a canvas from the strips, and the review gallery is a chat
artifact built from the frames.

## Tooling

```bash
pip install -r requirements.txt          # repo root
export PIXELLAB_API_KEY=...              # gitignored .env; never committed

python monsters/pipeline/sync.py             # THE command: discover by tag,
                                             #   mirror all, prune, rebuild
                                             #   animation_map, verify
python monsters/pipeline/sync.py --dry-run   # print the plan only
python monsters/pipeline/sync.py --fresh     # wipe folders, full re-download
python monsters/pipeline/sync.py --only <id> # limit mirroring to one monster
```

- `config/roster.json` — reconciled by sync: pins each tagged monster's stable
  folder id, display name, short wiki `lore` blurb and animation `renames`
  (exact PixelLab animation name → state). Hand-tune freely; sync preserves entries across runs and
  drops ones whose tag disappeared. Newly tagged monsters get best-effort
  renames from `pipeline/states.py` and are flagged for review.
- `pipeline/sync.py` — the reconciler (discover → prune → mirror → contract
  files → verify). Does not commit; the caller commits one atomic change.
- `pipeline/mirror.py` — mirrors ONE monster (either store) into the layout
  above; builds the per-direction sprite-sheet strips.
- `pipeline/postprocess.py` — repairs PixelLab's wrap-around overflow bug
  (graphics drawn outside the canvas re-appear wrapped to the opposite edge,
  usually on the NEXT frame). Detects wrapped strips via seam continuity,
  grows the monster's canvas symmetrically (manifest keeps `native_size` +
  `postprocess.pad`), restores the strip beyond the original border on its
  true frame and cleans the frame it wrapped onto. Human-reviewed exceptions
  (radial spike/droplet debris that only LOOKS wrapped) live in
  `config/wrap_overrides.json`. Runs automatically inside sync.
- `pipeline/states.py` — keyword classifier used only for brand-new monsters
  nobody has mapped yet.
- `pipeline/review_artifact.py` — emits the self-contained review gallery HTML
  (animations embedded as lossless WebP sheets + a canvas animator) for the
  chat artifact; output stays out of git.
- `pipeline/pixellab_client.py` — this domain's own client: tag discovery with
  pagination, both stores' animation shapes normalized to one, threaded
  CDN downloads, If-Modified-Since change detection.

## How this agent runs

- **No automated loop yet.** On demand: the maintainer tags/authors monsters
  on PixelLab and asks for a resync.
- Commits go **directly to `main`**, touching only `monsters/` and
  `coordination/monsters.json` (one writer per file).
- Mirroring is free; the shared PixelLab generation budget is only spent when
  *generating* new art.
